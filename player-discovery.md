# Local player discovery

`RelayPlayerDiscovery.Scan()` observes players without logging in or changing playback. It returns devices, scanned networks, an address count, and brief warnings. The player manager must still use the existing checked connection/login flow before controls or uploads; discovery does not create a checked connection.

The implementation reuses the packet format and parser already verified against installed ViPlex Express 3.0.5.1501. It sends the existing read-only discovery query to UDP ports 16601 and 16611. Replies are accepted only from those ports and from an address inside the selected scan range. The sender address is used, rather than an address embedded in the response.

Because UDP discovery has been unreliable on this Wi-Fi network, the scan also probes the fixed HTTPS port 16674 and `GET /terminal/core/v1/version` endpoint. This endpoint supplied unauthenticated serial and model information during the earlier live T50 work. The request sends no password, authorization header, cookie, or request body; redirects are disabled. A discovery response is capped at 64 KiB and must have `code:0`, a data object, and a serial compatible with Relay's player IDs. Unauthenticated version dimensions are not interpreted as output geometry. A certificate fingerprint is captured for the observation, but the normal connection check remains authoritative before credentials or operations.

Only active physical Ethernet or Wi-Fi IPv4 interfaces in RFC1918/link-local ranges are considered. Loopback, VPN, virtual, tunnel, and Tailscale adapters are excluded. Each interface is limited to the containing /24, or its actual subnet when smaller; the computer's own address, subnet address, and broadcast address are excluded. A larger subnet therefore needs manual addresses for boards outside the scanned /24. At most four interfaces are scanned, with 24 concurrent HTTPS probes, a 1.8-second per-host deadline, and an 85-second overall fallback budget. A reset GET can retry once within the same per-host deadline; closed ports, timeouts, invalid responses and redirects are not retried. UDP listens for 2.4 seconds per interface before HTTPS and again afterward to recover from lost replies.

Results are deduplicated by serial. For the same serial and address, HTTPS identity observations take priority over duplicate UDP identities while retaining UDP output dimensions when available. These are discovery observations, not proof of successful login or playback.

Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\player-discovery.test.ps1` for pure scope/parser checks and loopback HTTP tests. Tests cover narrow and capped broad subnets, excluded address classes, self/broadcast rejection, serial deduplication, fixed GET-only behavior, absence of credentials, redirect rejection, and response-size limits. Tests never scan the real network.
